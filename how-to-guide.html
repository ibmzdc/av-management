First-time token setup (one-off, ~1 minute)

The admin page needs a GitHub token to save data. You only do this once per browser/device.

  1. 1
    Open the admin page with your token in the URL

    Replace YOUR_TOKEN with your actual GitHub personal access token:

    https://ibmzdc.github.io/av-management/admin.html#YOUR_TOKEN

    The page reads the token, saves it to your browser, and removes it from the URL bar automatically.

  2. 2
    Confirm the ✅ appears

    The GitHub access token panel at the top of the page will show: ✅ Token saved in this browser — auto-populated on every visit.

  3. 3
    Bookmark the clean URL

    After the token is stripped from the URL bar, bookmark the plain address: https://ibmzdc.github.io/av-management/admin.html. Every future visit auto-loads the token and the data.

If you switch to a new browser or device, repeat this step once on that browser. Alternatively, paste the token directly into the token input field on the page and click Set token.

Daily workflow

Marking a file as Ready and adding its download link

Do this each time a presenter delivers a final file and you've uploaded it to Box.

  1. 1
    Upload the file to Box

    Drop the final .pptx, .pdf, or .mp4 into your Box folder and share it with the AV vendor team's Box accounts.

  2. 2
    Get the Box direct download link

    Right-click the file in Box → Share → Copy Link. Change the URL format:

    From: https://ibm.box.com/s/xxxxxxx
    To: https://ibm.box.com/shared/static/xxxxxxx.pptx

    The /shared/static/ format forces a direct download instead of opening the Box preview page.

  3. 3
    Open the admin page and find the session

    Go to admin.html → locate the correct day and session → click Edit.

  4. 4
    Update the session fields

    In the edit modal, make these changes:

    FieldWhat to set
    StatusChange to Ready (first time) or Updated (if replacing a prior version)
    Download URLPaste the Box direct download link from Step 2
    Updated atTime you received the file, e.g. 9:15 AM
    Updated noteBrief note, e.g. Final version from presenter
    FreshnessSet to New (first time) or Changed (replacement)
  5. 5
    Optionally add a change log entry

    Scroll to the Change log entry section in the modal. Fill in Time, Title, and Description — this appears in the vendor's dashboard change log feed so they can see what changed and when.

  6. 6
    Click Save session

    The modal closes and the session table updates.

  7. 7
    Click 💾 Save to GitHub

    This commits all your changes directly to the GitHub repository. The live dashboard updates within about 30 seconds. You'll see a green confirmation message with the save timestamp.

Important: Changes are only live after clicking 💾 Save to GitHub. Editing sessions without saving leaves changes in the browser only.

Adding a new session

  1. 1
    Click "+ Add session" next to the correct day header.
  2. 2
    Fill in all fields in the modal — time, title, file name, type, status, and AV details.
  3. 3
    Click Save session, then 💾 Save to GitHub.

Adding a new event day

  1. 1
    Type the day label in the Add a new day field, e.g. Day 1 · October 19.
  2. 2
    Click Add day. The new empty day appears at the bottom.
  3. 3
    Add sessions to the new day, then 💾 Save to GitHub.

Updating the Last Refresh timestamp

The Last dashboard refresh field at the top of the dashboard shows the vendor when data was last updated. Set it each time you make a batch of changes before saving.

  1. 1
    Click the Last refresh date & time field at the top of the editor and pick the current date and time.
  2. 2
    Click 💾 Save to GitHub.

AV Vendor Team

Reading the dashboard

Status badges

Every session file has one of three statuses:

BadgeMeaningAction
ReadyFile is approved and ready for projection.Download and load onto the playback machine.
UpdatedA newer version was received today.Download immediately and replace your local copy.
On holdFile not yet received from presenter.Do not project. Check back later.

Downloading a file

  1. 1
    Confirm the status is Ready or Updated

    Never download a file marked On hold — it may be incomplete.

  2. 2
    Click Download latest

    The link downloads directly from IBM Box. You will need to be logged into Box with your IBM-shared account to access the file.

  3. 3
    Check the timestamp

    The Updated at column shows when the file was last changed. Always use the most recent version — if you already have an older copy, replace it.

  4. 4
    Keep a local backup

    For any file already used on stage, keep one backup copy on the playback machine before replacing it.

Filtering and searching

Use the four controls at the top of the dashboard to narrow the file list:

ControlUse it to…
Event dayFilter to a single day, or view all days at once.
StatusShow only Approved for projection files, Updated today, On hold, or all files.
SearchType any part of a session title or file name to find it instantly.
SortSort by most recently updated, session time, or file name.

Viewing AV production details

Each session row includes a View AV details button (where details have been entered). Click it to expand the full AV setup for that session:

DetailWhat it covers
MicrophonesNumber and type of mics required on stage.
Stage setupPhysical layout — podium, panel, fireside, etc.
Confidence monitorWhether a confidence monitor is needed and where.
ClickerWhether a slide clicker is required.
TimerSession length or countdown timer setting.
Special AV notesAnything non-standard — walk-on music, live demo, audio levels, etc.

Today's change log

The change log panel (bottom left of the dashboard) lists every update made since the last refresh — newest first. Check it at the start of each session block to catch any last-minute file swaps or status changes.

Operational rules

  • Only download files marked Ready or Updated.
  • Always use the file with the most recent Updated at timestamp.
  • Keep one local backup of any file already cued or played on stage.
  • Check the dashboard before each session block — not just once in the morning.
  • If a file shows Updated, download it immediately and replace your local copy before that session begins.
  • If a file remains On hold close to session time, alert the AV lead immediately.

How quickly do changes appear on the dashboard?

After clicking 💾 Save to GitHub on the admin page, GitHub Pages rebuilds and the dashboard reflects changes within approximately 30–60 seconds. The vendor team just needs to refresh their browser.

Who to contact

If the dashboard shows an error, a file is missing, or a status hasn't updated — contact the AV lead directly. Do not attempt to edit the admin page.
