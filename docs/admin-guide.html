First-time token setup (one-off, ~2 minutes)

The admin page needs a GitHub personal access token to save data back to the repository. You only do this once per browser or device.

  1. 1
    Open the admin page with your token appended to the URL

    Paste this into your browser address bar, replacing YOUR_TOKEN with your actual token:

    https://ibmzdc.github.io/av-management/admin.html#YOUR_TOKEN

    The page reads the token from the # fragment, saves it to your browser's local storage, and removes it from the URL bar — all automatically.

  2. 2
    Confirm the ✅ appears in the token panel

    The GitHub access token panel at the top of the admin page will show: ✅ Token saved in this browser — auto-populated on every visit.

  3. 3
    Bookmark the clean URL

    Once the token is stripped from the address bar, bookmark the plain URL. Every future visit auto-loads the token and the session data with no action required.

On a new browser or device, repeat this step once. Alternatively, paste the token directly into the input field on the page and click Set token.

Daily workflow

When a presenter delivers a final file

Files are managed in Box. Your workflow: upload → set status → save. The dashboard auto-detects updates.

  1. 1
    Upload the file to Box

    Drop the final .pptx, .pdf, or .mp4 into your Box folder (organized by session or day). Share it with the AV vendor team's Box accounts so they can download it.

  2. 2
    Open the admin page and find the session

    Go to admin.html, locate the correct day and session in the table, then click Edit.

  3. 3
    Update status (required) and optional fields
    FieldWhat to do
    StatusReady for first delivery, or Updated when replacing a prior version. Timestamp auto-sets on save.
    FreshnessNew to highlight first-time file. Changed to highlight a replacement. (Optional)
    AV detailsUpdate if needed (mics, stage setup, etc.). Optional.
    Operator notesSession-specific instructions for the AV team. Optional.
  4. 4
    Add a change log entry (optional but recommended)

    Scroll to the Change log entry section. Fill in Time, Title, and Description. This appears in the AV team's dashboard so they know exactly what changed and when.

  5. 5
    Click Save session

    The modal closes and the session row updates in the table. Status timestamp is auto-set to current time.

  6. 6
    Click 💾 Save to GitHub

    This commits all pending changes to the GitHub repository. The live dashboard reflects updates within approximately 30–60 seconds. The AV team will see a "New version available" indicator.

Tip: The admin form only asks for essential metadata now. Download URL management is removed entirely — files are tracked by status and timestamp in Box.

Adding a new session to an existing day

  1. 1
    Click "+ Add session" next to the day header you want to add to.
  2. 2
    Fill in all fields in the modal — time, title, file name, type, status, and AV production details.
  3. 3
    Click Save session, then 💾 Save to GitHub.

Adding a new event day

  1. 1
    Type the day label in the Add a new day field at the top of the editor, e.g. Day 2 · October 20.
  2. 2
    Click Add day. The new empty day appears at the bottom of the session list.
  3. 3
    Add sessions to the new day, then 💾 Save to GitHub.

Updating the Last Refresh timestamp

The Last dashboard refresh box in the dashboard header tells the AV team when data was last updated. Update it whenever you make a batch of changes.

  1. 1
    Click the Last refresh date & time field at the top of the editor and set it to the current date and time.
  2. 2
    Click 💾 Save to GitHub.

Deleting a session

Click Delete on the session row. Confirm the prompt. Then click 💾 Save to GitHub to publish the removal.

Deletions are permanent once saved to GitHub. There is no undo — the data is committed to the repository history, but restoring it requires a GitHub rollback.
