01

System overview & architecture

What it does

The AV Management System gives an event AV lead a single place to track presentation and video files across all event days. The vendor AV team gets a live, read-only dashboard showing which files are approved, updated, or on hold — with direct download links, AV production requirements per session, and a change log feed.

All data lives in a single JSON file committed to a GitHub repository. The admin edits data through a browser-based form and saves it via the GitHub Contents API — no server, no command line, no file drag required.

  • Download links point to IBM Box shared files — Box controls who can actually download
  • Latency: ~30–60 seconds from admin save to live dashboard update

Data model — av-data.json

Top-level structure

{
  "lastRefresh": "October 19, 2026 · 9:00 AM",
  "days": [ ...array of day objects... ]
}
FieldTypeDescription
lastRefreshstringHuman-readable timestamp shown in the dashboard header. Set by the admin before each save.
daysarrayOrdered array of event day objects.

Day object

{
  "id": "day-1",
  "label": "Day 1 · October 19",
  "files": [ ...array of session file objects... ],
  "changeLog": [ ...array of change log entries... ]
}
FieldTypeDescription
idstringUnique identifier, e.g. day-1. Used as a DOM key and filter value.
labelstringDisplay name shown in the day selector and table headers.
filesarraySession file objects for this day.
changeLogarrayChange log entries shown in the dashboard timeline panel.

Session file object

{
  "sessionTime": "08:30",
  "sessionTitle": "Welcome & Opening Remarks",
  "fileName": "Day1-Opening Remarks.pptx",
  "type": "Presentation",
  "status": "ready",
  "freshness": "new",
  "updatedAt": "8:45 AM",
  "updatedNote": "Final version from presenter",
  "notes": ["Do not project until status is Ready"],
  "downloadUrl": "https://ibm.box.com/shared/static/xxxxx.pptx",
  "avDetails": {
    "microphones": "2 handheld, 1 lav",
    "stageSetup": "Podium",
    "confidenceMonitor": "Yes, downstage center",
    "clicker": "Yes",
    "timer": "30",
    "specialNotes": ""
  }
}
FieldValuesDescription
sessionTimeHH:MM or H:MM AM/PMSession start time. Used for sorting. Both 24h and 12h formats accepted.
sessionTitlestringFull session name.
fileNamestringExact filename with extension.
typePresentation · VideoFile type used for the Videos stat counter.
statusready · updated · holdCore status driving badge colour and download link visibility.
freshnessnew · changed · omitOptional. Highlights row with a colour band and badge. Clear once acknowledged.
updatedAtstringTime file was received, e.g. 9:15 AM or Pending.
updatedNotestringShort description of the most recent change.
notesstring[]Array of operator notes shown as a bullet list on the dashboard.
downloadUrlURL stringBox direct download link. Use # as placeholder until file is uploaded.
avDetailsobjectAV production requirements. All sub-fields are strings. Shown in expandable row.

Change log entry object

{
  "time": "9:20 AM",
  "title": "Deck updated",
  "description": "Replace the preloaded copy with this version."
}

Entries are displayed newest-first in the dashboard timeline panel, filtered to the selected day.

04

How each page works

dashboard.html — AV team read-only view

  • On load calls fetch(DATA_URL + '?t=' + Date.now()) against raw.githubusercontent.com/[org]/[repo]/main/data/av-data.json. Cache-busting query param ensures freshest data on every refresh.
  • If fetch fails, retries automatically every 10 seconds.
  • Renders a filterable/sortable table of sessions, a summary stat bar, a change log timeline, and expandable AV detail rows per session.
  • Download links use the downloadUrl field directly — Box handles authentication.
  • No authentication, no write access, no local state beyond the fetched JSON.

Key constant to update per event:

const DATA_URL = 'https://raw.githubusercontent.com/[ORG]/[REPO]/main/data/av-data.json';

admin.html — Admin edit & save UI

  • On load calls the GitHub Contents API (GET /repos/[org]/[repo]/contents/data/av-data.json) using the stored token. This returns the file content (base64-encoded) and its current SHA.
  • Content is decoded via Uint8Array + TextDecoder('utf-8') to correctly handle multi-byte characters (e.g. middle dot ·).
  • The admin edits sessions via a modal form. All changes are held in memory until the admin clicks 💾 Save to GitHub.
  • Save calls PUT /repos/[org]/[repo]/contents/data/av-data.json with the updated base64 content, a commit message, and the file's current SHA (required by GitHub to prevent conflicts).
  • On success, the returned SHA is stored in memory for the next save.
  • Token is read from: (1) window.location.hash on first visit, then stored to localStorage; (2) localStorage on all subsequent visits.

Key constants to update per event:

const REPO      = '[ORG]/[REPO]';
const BRANCH    = 'main';
const FILE_PATH = 'data/av-data.json';
const API_URL   = `https://api.github.com/repos/${REPO}/contents/${FILE_PATH}`;

index.html — Root redirect

A single <meta http-equiv="refresh"> redirect to app/dashboard.html. Ensures the root GitHub Pages URL (https://[org].github.io/[repo]/) opens the dashboard automatically. Must stay at the repo root — not inside app/.

docs/admin-guide.html & docs/av-team-guide.html

Self-contained static HTML how-to guides. No JavaScript. Styled with the same CSS design system as the other pages. Update text content only when re-deploying for a new event — no code changes needed.

05

GitHub Pages setup

Requirements

  • Repository must be public for GitHub Pages on a free plan. Private repos require GitHub Team ($4/user/month) or higher.
  • Pages must be enabled with source: branch main, root path /.
  • HTTPS is enforced automatically by GitHub Pages — required for the GitHub Contents API to work from the browser.

Enable via API (one-time)

curl -X POST \
  -H "Authorization: token YOUR_TOKEN" \
  -H "Accept: application/vnd.github.v3+json" \
  https://api.github.com/repos/[ORG]/[REPO]/pages \
  -d '{"source":{"branch":"main","path":"/"}}'

Enable via GitHub UI

Repository → Settings → Pages → Source: Deploy from branch → Branch: main → Folder: / (root) → Save.

Resulting URL pattern

https://[ORG].github.io/[REPO]/app/dashboard.html
https://[ORG].github.io/[REPO]/app/admin.html
https://[ORG].github.io/[REPO]/docs/admin-guide.html
https://[ORG].github.io/[REPO]/docs/av-team-guide.html
06

Authentication — GitHub token

Token requirements

  • Type: Personal Access Token (classic)
  • Required scope: repo (full repository access)
  • Expiry: set to no expiration for event use, or 90 days for tighter security
  • The token must belong to an account that has write access to the repository

How the token is stored

  • Never hardcoded in any file — the repository is public
  • Stored in localStorage under the key gh_token on the ibmzdc.github.io origin
  • Scoped to that origin only — cannot be read by other websites
  • Cleared by clicking Clear in the token panel, or by clearing browser data

First-time setup method (hash fragment)

Open this URL once in the admin's browser — the page extracts the token, saves it to localStorage, and strips it from the address bar:

https://[ORG].github.io/[REPO]/admin.html#YOUR_TOKEN

Do not share this URL with anyone. The hash fragment is client-side only and not sent to GitHub's servers, but it is visible in browser history on the device used.

07

IBM Box integration

Role of Box in this system

Box is used exclusively for file storage and access control. The AV system itself (dashboard, admin, data) does not integrate with the Box API — it only stores Box shared links as strings inside av-data.json.

Box direct download link format

Shared links copied from Box use the preview URL format. They must be converted to the direct download format before being entered into the admin page:

Preview URL:  https://ibm.box.com/s/xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Direct URL:   https://ibm.box.com/shared/static/xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.pptx

Replace /s/ with /shared/static/ and append the file extension. This forces an immediate download instead of opening the Box preview page.

Access control

  • The dashboard URL and data JSON are public — anyone can read session metadata
  • Box file access is controlled separately by Box sharing settings
  • Share files with the AV vendor team's Box accounts directly, not as "Anyone with the link" unless you intend public access
  • The files/ folder in Box Drive is the recommended upload location for all event media files

Re-onboarding for a new event

Checklist — new event setup

  1. Create a new GitHub repository under the event organisation (e.g. ibmzdc/av-management-2027-spring).
    • Set to public
    • Default branch: main
  2. Copy all files from the previous event's av-management/ folder into the new repo:
    • index.html, dashboard.html, admin.html
    • admin-guide.html, av-team-guide.html
    • data/av-data.json
  3. Update constants in dashboard.html and admin.html (see Section 4):
    • REPO — new repo name
    • DATA_URL — new raw GitHub URL
    • Page <title> tags and <h1> headings
  4. Reset av-data.json — clear all days and sessions, update lastRefresh, add the new event's day structure. Use the admin page's Start from blank template button as a starting point.
  5. Enable GitHub Pages on the new repo (see Section 5).
  6. Generate a new GitHub token (or reuse an existing one with repo access) and set it in the admin browser using the hash fragment method (see Section 6).
  7. Create a new Box Drive folder for the event. Create a files/ subfolder for presentation uploads.
  8. Share the new dashboard URL with the AV vendor team and the AV team guide URL.

The entire setup — from creating the repo to having a live dashboard — takes approximately 15 minutes.

Customisation reference

Adding a new status type

Status values are driven by the status field in the JSON. To add a new status:

  1. Add a CSS rule in app/dashboard.html: .badge-[name] { color: ...; background: ...; }
  2. Add the value to the statusLabels and statusClasses objects in the dashboard script
  3. Add the option to the <select id="m-status"> dropdown in app/admin.html
  4. Add the filter option to <select id="status"> in app/dashboard.html if you want it as a filter

Adding a new session field

  1. Add the field to the JSON schema (edit a session in admin to populate it)
  2. Add an input to the modal in app/admin.html
  3. Read and write the field in openModal() and saveModal() functions
  4. Render the field in renderFileRows() in app/dashboard.html if it should be visible

Changing the auto-refresh interval on the dashboard

The dashboard does not auto-refresh. It fetches once on load and again on manual browser refresh. To add auto-refresh, insert this at the bottom of the dashboard script:

setInterval(initialize, 60000); // refresh every 60 seconds

Known limitations

LimitationImpactWorkaround / Notes
Dashboard data is publicSession titles, AV notes, and Box URLs are readable by anyone with the GitHub URLBox controls actual file downloads. Session metadata is not sensitive. Make repo private + upgrade to GitHub Team if required.
~30–60s publish delayAfter admin saves, dashboard takes up to 60s to show updated dataVendor team must refresh their browser. Consider adding auto-refresh interval (see Section 9).
Single admin userConcurrent edits from two browsers will cause the second save to fail (SHA mismatch)Designed for one admin. The second save will show an error and the admin must reload and re-apply changes.
No edit history UIAdmin cannot see previous versions of session dataFull history is preserved in the GitHub commit log at github.com/[org]/[repo]/commits/main.
Token in localStorageAnyone with physical access to the admin's browser can extract the token from DevToolsUse a token with minimal required scope. Revoke and regenerate the token after the event.
No offline supportDashboard requires internet access to fetch dataDashboard falls back to a retry loop on failure. Consider embedding fallback data for offline use.
